# 个人 AI 工作台 · 架构文档

> 面向维护者与贡献者的系统结构说明。配套决策记录见 `docs/adr/`，上手操作见 `docs/开发文档.md`。
> 更新基线：2026-08-27（Agent 板块 M1 + 网络搜索 MCP 接入后）。

## 1. 系统总览

npm workspaces 单仓三包：`server`（Express API）、`web`（React SPA）、`e2e`（Playwright）。零数据库——一切持久化皆为纯文本文件（[ADR-0001](adr/0001-markdown-as-data-source.md)）。

```
┌──────────────┐   HTTP/JSON·SSE    ┌──────────────────┐   直接读写文件   ┌─────────────────┐
│  web :5277   │──────────────────▶│  server :5233    │───────────────▶│ data/           │
│  React SPA   │◀──────────────────│  Express API     │                │ ├ users/*.md    │
│  (Vite)      │                   │                  │                │ ├ ideas/ … *.md │
└──────────────┘                   └────────┬─────────┘                │ ├ agent/threads │
        ▲                                   │ HTTPS                    │ │  └─*.json     │
        │ 浏览器                            ▼                          │ ├ config/       │
        └────────────────────── /api 代理（Vite dev proxy）             └─────────────────┘
                                    │
                     ┌──────────────┴──────────────┐
                     ▼                             ▼
             GLM 等大模型供应商              bigmodel 搜索 MCP
             （Anthropic 兼容端点等）         web_search_prime
```

**端口是永久约定**：后端 5233 / 前端 5277（均可 `PORT` 覆盖；Vite `strictPort` 被占即报错，绝不静默换端口）。e2e 走隔离端口 3100/5174 + 独立数据目录。

## 2. 服务端分层（`server/src/`）

| 层 | 目录 | 职责 |
|---|---|---|
| 组装 | `api/app.ts` | 中间件（json/cookie/trust proxy）、按板块挂路由、统一错误处理（ZodError→400，AiError→503，其余→500）|
| 路由 | `api/routes/*.ts` | auth / ideas / goals / tasks / today / reviews / opportunities / reports / finance / agent |
| 鉴权 | `auth/` | 用户文件存储、bcrypt 校验、JWT、按 IP 登录阶梯锁定 |
| 存储 | `storage/`、`agent/threadStore.ts` | EntityStore（md+frontmatter）、ReviewStore、ThreadStore（JSON，见 ADR-0004）|
| AI | `ai/` | scoreClient（想法评分）、reportClient（报告生成）——Agent 之外的两处轻量 LLM 集成 |
| Agent | `agent/` + `api/routes/agent.ts` | 本文档第 3 节重点 |
| CLI | `cli/` | `add-user` / `reset-password`（npm scripts 直连 tsx）|

**数据即文件**：除 Agent 会话（ADR-0004 定向豁免为 JSON）外一切实体 = 一个带 frontmatter 的 `.md`；`data/` 不进 git，git 即备份通道。

## 3. Agent 板块（核心子系统）

### 3.1 一次对话的完整链路

```
浏览器 useChatRuntime
   │  POST /api/agent/chat (JWT)
   ▼
routes/agent.ts
   │ 1 zod 校验 → ThreadStore.get/create（不存在的会话 id 即刻占位）
   │ 2 resolveModel(selection) ← 三级模型解析（3.2）
   │ 3 getWebSearchTools() ← MCP 桥接（3.3，失败降级空集）
   │ 4 streamText({ model, messages, maxOutputTokens:32768, tools, stopWhen: stepCountIs(5) })
   │      └─ agent 循环：模型可 思考→调工具→读结果→再调→总结，≤5 步自动续跑
   │ 5 createUIMessageStream(merge(stream)) → pipeUIMessageStreamToResponse
   ▼
SSE: UIMessage Stream 分片（start / reasoning-delta / text-delta / tool-* / finish）
   │  onEnd：合并后的完整 messages 全量覆写回会话 JSON + 派生标题 + 记 usage
   ▼
前端 assistant-ui 逐部件渲染；ThreadStore JSON 即历史，刷新 getThread 原样恢复
```

### 3.2 模型解析三级降序（`agent/modelResolver.ts`）

1. `WORKBENCH_AGENT_FAKE=1` → 确定性假模型（`ai/test` Mock），离线 e2e / 无 Key 演示
2. `data/config/ai-providers.json`（后台页可视化读写，密钥读时打码）→ 按 `providerId/defaultModel` 选取
3. 环境变量兜底 `WORKBENCH_AI_*`（BASE_URL 含 `/anthropic` → anthropic 协议，否则 openai-compatible）

厂商按 `kind` 实例化：`openai` / `anthropic` / `deepseek` / `openai-compatible` / `fake`（[ADR-0005](adr/0005-agent-engine-vercel-ai-sdk.md)）。GLM 的 Anthropic 兼容端点走 `@ai-sdk/anthropic`，baseURL 缺 `/v1` 时自动补齐（否则打中错误路径，返回 200+JSON 错误体 → 流静默无输出）。

### 3.3 工具与 MCP（`agent/webSearch.ts`）

```
streamText.tools ◀── 桥接层 ◀── @modelcontextprotocol/sdk Client
                     listTools() 动态枚举（不写死工具名）
                     jsonSchema() 转 AI SDK schema
                     execute() → callTool()（45s 超时，text 结果拼接）
                                ↓ Streamable HTTP + Bearer
                          open.bigmodel.cn/api/mcp/web_search_prime/mcp
```

- 进程级缓存 15 分钟免重复握手；**任何失败降级为无工具**，不阻塞对话主链路
- 密钥优先级：`WORKBENCH_SEARCH_API_KEY` > 配置文件 `webSearch.mcpApiKey` > 主模型 Key；`WORKBENCH_SEARCH_MCP=0` 显式关闭
- 实测远端工具名 `web_search_prime`（与官方文档 `webSearchPrime` 不符）——运行时枚举策略天然免疫此类漂移
- `ai@7` 已移除 `experimental_createMCPClient`，官方 MCP SDK 直桥接是当前标准路径，也是后续接任意 MCP server 的统一入口

### 3.4 已知关键陷阱（修复实录，防回归）

| 陷阱 | 现象 | 对策（已内建） |
|---|---|---|
| `@ai-sdk/anthropic` 对未知模型名钳默认 `maxOutputTokens=4096` | glm-5.3 长思考烧光配额 → `finish=length`、正文零字 | `streamText` 显式 `maxOutputTokens`（env 可覆盖）；换新模型时务必复核该值 |
| Node≥16 `req.on('close')` 正常完成也触发 | 流收尾瞬间被 abort，打断合并落盘 | `if (!res.writableEnded)` 才 abort |
| assistant-ui 外层线程 id 是 `__LOCALID_*` | 消息落孤儿线程，侧栏空白、刷新丢失 | transport `prepareSendMessagesRequest` 强制改写为服务端 id |
| Vite 多实例共享 deps 缓存互踩 | 504 Outdated Optimize Dep 整站白屏 | 隔离实例独立 `cacheDir: node_modules/.vite-isolated` |

### 3.5 前端运行时（`web/src/pages/`）

- **三栏** AgentPage：会话列表（自管 REST）｜对话视口｜产物预览位（M2）
- **线程切换 = remount**：`RuntimeGate key={threadId}`，`useChatRuntime({ transport, id, messages })` 以服务端历史初始化
- **部件化渲染**：`MessagePrimitive.Parts` 按类型映射——`Text`（remark-gfm 表格）、`Reasoning`（ReasoningFold 折叠块：直播自动展开 → 正文出现/运行结束即收口；仅末条气泡可直播，正文限高滚动）、`tools`（🌐 搜索卡 + 未注册工具兜底卡）
