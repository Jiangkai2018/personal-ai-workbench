# ADR-0008：会话即长任务（断连续跑 + 完成推送，不建独立任务实体）

## 背景

0828-01 需求要求支持长任务（深度调研、批量落盘可跑数分钟）完成后钉钉推送，而运行期间用户可能关页/断网。可选路径：A) 把长任务建成独立实体（任务表、状态机、任务看板）；B) 直接把「会话的一次运行」当作长任务。

## 决策

**会话即长任务**：会话级开关「完成后推送」（thread JSON `pushOnCompletion`）开启时，`/chat` 运行不随客户端断连而中止——服务端跑完、onEnd 落盘、触发推送。不引入独立任务实体。

配套语义：手动停止（stop 端点 abort 并打标 `manual-stop`）不推送；意外断开（关页/断网）续跑并推送；未开开关的会话保持现状「断开即中止」。同一会话运行互斥（运行中再发 → 409），全局后台运行上限 3、超限拒绝不排队。

## 理由

独立任务实体要造状态机、持久化与看板 UI，是为「跑完通知我」这一期唯一诉求付出的系统级复杂度；会话运行本身已具备全部要素（AbortController、onEnd 落盘、用量统计），只需改断连策略 + 加内存运行表。v1 明确接受的代价：运行态仅在内存，服务重启丢状态（status 退回 not-running；已落盘结果不受影响）。

## 后果

- `/chat` 的 `req.on('close')` 中止逻辑按开关分流：开关开启 → 不 abort，跑完落盘再推送
- 前端轮询 `GET /api/agent/threads/:id/status`；重开页面凭「运行中」标记恢复视图
- 若未来出现真正的任务看板需求（排队、并发可视、历史任务），另立新 ADR 升级，届时本决策被 supersede
