# ADR-0003：转正直达，移除确认中心

- 状态：已接受
- 日期：2026-08-22
- 取代：[ADR-0002](0002-proposal-confirmation-gate.md)

## 背景

ADR-0002 为"想法→机会、机会→目标"的转正设置了提案门：Agent 只能提案，用户到确认中心批准后才生效。设计初衷是给承诺加摩擦、并为未来 Agent 预留安全边界。

实际使用后的结论：**单人自用场景下，这道门的摩擦远大于收益**。用户每次转正都要跳页面、找提案、点批准 —— 时间花在了流程上而不是执行上。产品原则是"把时间留在执行上"。

## 决策

**移除确认中心，转正一键直达：**

- `POST /api/ideas/:id/promote`：想法直接创建为机会，并**自动触发 AI 5 维初评**（AI 不可用时以 0 分创建，不阻塞）
- `POST /api/opportunities/:id/promote-to-goal`：机会直接创建为目标
- 提案实体（proposals）与确认中心页面整体移除

**保留的安全边界（替代原提案门的职责）：**

1. **AI 只建议，不承诺**：AI 初评只能填充分数（`ai-score`/`ai-preview`），不能创建/修改目标等承诺实体；转正仍由用户点击触发
2. **不可逆操作仍有守卫**：已转正的想法不可删除（409），避免数据断链

## 理由

1. 单人系统里"提案人 = 批准人"，确认环节是纯摩擦
2. AI 初评承接了原提案门"过滤冲动承诺"的职能 —— 分数低的想法用户自然会重新考虑
3. 审计诉求降级：git 历史本身就是完整的操作留痕（ADR-0001）

## 后果

- 流程步数：转正从 3 步（提案→跳转→批准）降为 1 步
- 失去提案留档（谁何时批准）—— 由 git 历史兜底
- `data/proposals/` 目录弃用；未来若引入多用户协作，需重新评估提案门（届时以新 ADR 推翻本决策）
