# 个人 AI 工作台 · 开发文档

> 面向开发者的上手与日常操作手册。系统结构见 `docs/架构文档.md`，重大技术决策见 `docs/adr/`。

## 1. 环境准备

| 项 | 要求 |
|---|---|
| Node | ≥ 22（`engines` 已约束）|
| 安装 | 仓库根 `npm install`（workspaces 一次装全 server/web/e2e）|
| `.env` | 放仓库根（server 启动时 `process.loadEnvFile` 加载，**不覆盖已设置变量**）|

### .env 关键变量

| 变量 | 用途 | 缺省 |
|---|---|---|
| `WORKBENCH_AI_API_KEY` | 主模型 Key（GLM 等；搜索 MCP 缺省也用它）| 无则 Agent 报「未配置」|
| `WORKBENCH_AI_BASE_URL` | 模型端点；含 `/anthropic` → anthropic 协议 | `https://open.bigmodel.cn/api/anthropic` |
| `WORKBENCH_AI_MODEL` | 默认模型名 | `glm-5.3` |
| `WORKBENCH_SEARCH_API_KEY` | 搜索 MCP 专项 Key（可选）| 回退主模型 Key |
| `WORKBENCH_SEARCH_MCP_URL` | 搜索 MCP 端点（可选）| bigmodel web_search_prime |
| `WORKBENCH_SEARCH_MCP=0` | 显式关闭网络搜索工具 | 开启 |
| `WORKBENCH_AGENT_MAX_TOKENS` | Agent 单轮输出配额 | `32768` |
| `WORKBENCH_JWT_SECRET` | 生产必须改（默认密钥启动会打警告）| dev 默认值 |
| `WORKBENCH_DATA_DIR` | 数据目录 | `<repo>/data` |
| `WORKBENCH_AGENT_FAKE=1` | Agent 强制确定性假模型（离线 e2e/演示）| 真实模型 |
| `WORKBENCH_SSJ_*` | 随手记财务对接 | — |

多厂商配置也可用 `data/config/ai-providers.json`（`maskProviders` 读时打码，后台页 M4 可视化）。

## 2. 启动与常用命令（仓库根执行）

| 命令 | 说明 |
|---|---|
| `npm run dev` | 同时起 server:5233 + web:5277（concurrently；**-k 语义：一个挂全挂**）|
| `npm run dev:server` / `dev:web` | 单独起某端 |
| `npm run build` | server + web 构建 |
| `npm run test` | server 单测（vitest）|
| `npm run lint` | eslint（web/src + server/src + server/test）|
| `npm run e2e` | Playwright 全量（隔离端口 + `.tmp-data`，`--headed` 见 e2e:headed）|
| `npm run add-user -w server -- --username x --password y --name 名 --family` | 建号（无自助注册）|
| `npm run reset-password -w server -- ...` | 重置密码 |

> Windows 会话内起常驻 dev server 建议 `cmd start` 独立窗口（进程不随 shell 存亡、日志可见、可单独关闭）；登录页占位示例即真实账号名。

## 4. 测试

### 4.1 单测（vitest）

- `npm run test` / `test:watch`；server/test 覆盖存储层与路由契约。
- AI 依赖一律注入 fake（`createApp({ agentModelResolver, aiScorer, reportGenerator })` 均可注入）。

### 4.2 e2e（Playwright）

- 配置要点：`workers:1` 串行共享数据目录；webServer 自动拉起两端；浏览器通道复用本机 Chrome（`PLAYWRIGHT_CHANNEL=chromium` 可切）。
- **数据隔离铁律**：`fixture.ts` 每用例前清 `ideas/goals/…/agent` 目录——
  - 断言持久化时要轮询等待（onEnd 落盘是流结束后异步的）；
  - 绝不依赖上一用例遗留数据。
- 真实模型用例断言守则：**非空/增长类弱断言**（长度、稳定、结构），禁强绑具体文案；超时放宽（长思考 240s+）。
- 多步工具链一个气泡会产生**多个 `.ag-md` 文本段**（叙述与总结各一段）——统计文本要累加，不能只取首段。
- 截图/文档落 `local_docs/05.e2e测试/`，命名 `Tn-主题.md` / `bN-用例-描述.png`。

## 5. Agent 开发专题

### 加一个模型厂商
1. `agent/types.ts` 的 `ProviderKind` 不够用才加 kind；一般直接 `openai-compatible` 档即可。
2. 特殊端点归一化逻辑放 `modelResolver.instantiate`（参考 anthropic 档的 `/v1` 补全注释）。
3. **新模型名务必复核 `maxOutputTokens`**：unknown-model 会被 SDK 钳 4096，思考型模型会烧光配额、正文零字（bug082702-4 实录）。

### 加一个 MCP 工具源
1. 在 `agent/webSearch.ts` 抽出 `buildTools(target)` 泛化，或平行加一个 `getXxxTools`。
2. 保持三条纪律：**动态 listTools 枚举工具名**（不写死）、**execute 带超时**、**失败降级空集不阻塞对话**。
3. 路由侧 `tools` 合并即可，前端先有 Fallback 卡兜底，再做专属卡（参考 `WebSearchToolCard`）。

### Agent 前端注意
- transport `prepareSendMessagesRequest` 必须**改写请求体 id 为服务端会话 id**（外层 `__LOCALID_*` 会导致孤儿线程）。
- `ReasoningFold` 的直播态只允许**线程末条助手气泡**进入——历史 fold 被点亮即回归 bug082702-5。
- `ag-md` 渲染管线挂了 remark-gfm，表格/删除线/任务清单才可用。

## 6. 排障手册

| 症状 | 定位 | 处置 |
|---|---|---|
| 整站白屏，控制台 504 Outdated Optimize Dep | Vite deps 缓存互踩（多实例/装包后）| 删 `node_modules/.vite`（隔离实例删 `.vite-isolated`）重启 |
| 登录一直失败 | 按 IP 阶梯锁定触发 | 查 `data/security/banned.md`，等待或删除记录 |
| server 起不来 EADDRINUSE:5233 | 旧实例未杀（`npm run dev -k` 会连带全挂）| 杀 5233/5277 占用进程再启动 |
| 对话只有思考没有正文 | 配额被钳/上游断流 | 查落盘 JSON parts 形态（reasoning 截断+无 text = 配额问题）；确认 `WORKBENCH_AGENT_MAX_TOKENS` 未设小值 |
| 工具卡不出现 | MCP 连接失败会降级 | 看 server 日志「已连接搜索 MCP / 降级为无工具」行；`WORKBENCH_SEARCH_MCP=0` 也会关闭 |
| e2e 账号被锁 | 用例连续失败触发锁定 | global-setup 会重建 `.tmp-data`，重跑即可 |

## 7. 约定

- **提交纪律**：用户/维护者明确要求才 `git commit`；改动默认留工作区待验收。
- **测试数据纪律**：测试只动 `.tmp-data` 或自建测试账号，绝不触碰 `data/` 下真实用户数据。
- **文档**：结构性技术决策进 `docs/adr/`（短决策记录体）；bug 收集与修复实录在 `local_docs/01.迭代任务/`；端口 5233/5277 为永久约定。
